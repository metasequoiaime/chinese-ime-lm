# Agent Note: token 嵌入直接写入最终输入行

Status: implemented

## Problem

主项目固定 `5439b9675ca70a0ea4c3b7d51ec9f3d0420aca21`、完整锁定资源的默认 Runtime 九键十八秒采样，`linear_into` 和 `dot_i8` 分别有 1201 和 647 个栈顶样本，二元评分仍为另一主热点。采样从进程启动后三秒开始，含启动工作，不以其延迟作为成绩。源码另确认 `embed` 为每个 token 调用 `Matrix::row` 申请一行临时 Vec，再与位置相加到已经申请好的目标行，马上析构。此处工作量确定冗余，不据采样断言它是主要瓶颈。

## Decision

`Matrix::embed_row` 直接将浮点或按行缩放的 int8 token 值与位置逐项相加，写入目标行。保持先乘 scale 再加位置的运算顺序、token 越界裁剪及 position 饱和行为。只保留整次嵌入的输出 Vec；不增缓存、unsafe、依赖、常驻权重展开或公开接口。

## Existing decisions

检索 embedding、token.row、嵌入、矩阵行与反量化。没有旧 embedding 决定。[末层上文单行](../../implemented/bug-fix/2026-10-17-prefix-final-row.md)部分重叠，继续约束实际查询位置；[临时权重行反量化](../../rejected/testing/2026-10-17-linear-temporary-row-dequant.md)只影响点积的跨位置共享，失败决定保留，本项不改变矩阵乘法。其余矩阵行分派、交错及投影 scratch 的拒绝记录与此申请无关。没有完全吸收或过时提案。

## Alternatives considered

- 返回借用的浮点行、量化行仍物化：能少改量化入口且消除 Float 申请，但当前分发模型 token 为量化，主要入口仍保留临时行。
- 跨调用持有 token 行工作区：可保留原两次循环，但增加工作区状态与一次复制；目标行已经存在，直接写入更简单。

## Verification contract

先用完整冻结旧嵌入与当前生产入口跑相同 release 门槛，旧实现必须失败。宽 192/768、Float/Quantized、位置数 1/4/12/64 共 16 形状；每形状 21 对交替顺序，旧臂三次校准的最短值至少 5ms，包含输出和临时行申请析构，所有形状逐对 new/old 中位 <0.95。一次有效失败即拒绝，不放宽门槛或按结果挑形状。普通宽 1/7/8/9/192/768、空输入、超词表 token、偏移和上下文末端逐位对照，固定真实模型另验。完整旧新模型 bench 表、全测试、MSRV 1.75、Clippy、fmt；主项目固定接入另测逐键预算和完整质量。

## Consequences

消除申请不等于整体模型或九键明显提速；计时单独运行并监测构建进程，系统负载不证明独占。旧行物化只保留在冻结测试中。模型数值不允许改变，常驻存储不增加。

## Measurement corrections

第一次红测试遗漏旧体的 `FORWARD_POSITIONS` 测试计数，独立只读审查指出后补齐；不将这轮作为完整入口的量化证据。补齐后另发现单次校准被调度停顿放大，192 Float 单位置仅迭代 64 次、正式批次约 6us，不能解释成每臂 5ms。因此在首次计量新版前改为三次校准最短值达 5ms，并重跑旧实现红测试。原始形状汇总、全部已输出配对数据及构建监测一同保留；门槛、形状和配对数保持。最终数据只使用修正后的同一工具定义。

旧版完整模型 bench 首次运行有 112 次监测，其中 1 次观察到外部 rustc，耗时 119.51 秒；该整表只作为受干扰观察保留，不据此宣称模型收益。系统一分钟负载一度超过 100，不可能通过仅检查编译进程证明机器独占。

## References

[Rust Iterator::zip](https://doc.rust-lang.org/std/iter/trait.Iterator.html#method.zip) 的截短语义已核对；调用者提供严格等宽的目标和位置切片，沿用源码已有的迭代器写入模式。最低工具链另跑实际编译测试，不从当前文档版本推断兼容性。

## Results

当前工具链 release 与最低 Rust 1.75.0 各通过 45 项库测试、15 项模型文件测试和 doc tests，12 项手动测试默认忽略。固定真实模型 `real_embedding_matches_frozen_bits` 和 `real_model_forward_matches_legacy_bits` 另行通过；全目标 Clippy `-D warnings`、Rustfmt 通过。合成逐位对照覆盖 240 组形状、偏移与精度组合，含零 token、末 token 超词表、位置饱和及奇数宽度。独立只读审查确认算术、唯一调用者的等宽切片与修正后的测量入口，无生产正确性阻塞；审查没有运行测试或计时。

修正后旧实现完整门槛失败（25.36 秒、23 次监测无构建）。新版前两轮都通过，但分别 24/24、7/7 次监测有外部构建，只作受干扰观察。最后一次在连续三次无构建观察后启动，同一门槛 16 形状全过，4 次约一秒间隔监测均未观察到 cargo/rustc/clang。系统负载仍较高，不能证明机器独占，也不能排除采样间短进程。三次校准最短值达 5ms 不保证每个正式批次或新臂也达 5ms。

最终逐对中位 new/old 为 0.403–0.716。真实主宽 192 的量化单位置为 0.628684，4/12/64 位置为 0.454729/0.485536/0.478556；这些数只属于完整 embedding 入口，不是完整模型或九键速度比。所有 16 形状和共 1680 对已输出原始数据（包含工具修正诊断和受干扰轮次）见[测量结果](../../../../docs/measurements/2026-10-19-embedding-direct-write/results.json)和[配对数据](../../../../docs/measurements/2026-10-19-embedding-direct-write/paired.csv)。两次最早红测试与当前工具定义不同，不能混算最终分布。

复现命令：先 `cargo test --manifest-path reference/Cargo.toml --release --locked --no-run`，待构建终态并确保本任务其它计时停止后，直接执行输出的库测试二进制 `embedding_paired_budget --ignored --nocapture`；避免将 cargo 自身的编译算入测试计时。普通数值测试不使用墙钟。完整模型表及环境另附测量目录，不从受干扰表推断稳定整体收益。

此改动删除每 token 临时行的构造与析构，整次调用的输出 Vec 保持不变；不增加模型常驻内存、缓存寿命或跨平台指令。Rust 迭代器的逐项 scale、位置相加顺序不变。主项目需要在固定合并提交后独立验证质量与逐键预算，本仓库测量不替代该验收。

## Full model observations

完整旧新表分别见[旧版](../../../../docs/measurements/2026-10-19-embedding-direct-write/full-model-old.txt)和[新版](../../../../docs/measurements/2026-10-19-embedding-direct-write/full-model-new.txt)，均为固定模型、九键 81 例、每格 40 次。旧版54.40秒、52次监测无构建，一分钟负载32.35–37.98；新版100.16秒、93次监测无构建，负载24.06–64.86。它们不是同进程配对，没有证明整机空闲。旧版较早的112次监测有1次构建、新版较早66次监测有64次构建的两张受干扰表同样保留，不能选其中更好的数替代这两张。

单候选12字旧/新 p50 为5.55/5.58ms；9候选12字为46.28/51.23ms，p95为48.44/86.55ms。新版长形状更慢，不能从本轮排除整体回退，也不能宣称完整模型收益；本项采用依据是完整 embedding 入口同进程配对的16形状收益与逐位不变结果，主项目还需实际逐键对照。两表15字决策列无样本，0值不表示零成本；逐句15字行复用较短前缀池，不能当成真实15字决策。
