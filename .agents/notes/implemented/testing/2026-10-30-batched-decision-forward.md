# Agent Note: 一次决策的新位置当一批算

Status: implemented

## Problem

同一个 52 条候选池（`eval/open-models/pool.jsonl`）上，`pool.rs` 量到一次决策 4.25M 11.9 ms、24.9M 71.3 ms（Apple M4 Pro，单线程，`origin/main` `bd3210d`）。按阶段计时（临时插桩副本，不提交）：

| 阶段 | 4.25M | 24.9M |
|---|---|---|
| qkv / proj / fc / out 四个线性层 | 59.5% | 76.6% |
| 词表投影的点积 | 34.0% | 20.8% |
| 词表归一化的指数求和 | 2.7% | 0.7% |
| GELU | 2.0% | 1.0% |
| 注意力 | 0.4% | 0.2% |
| 层归一化、KV 拆分、嵌入、残差、其余（含申请） | 1.4% | 0.7% |

int8 点积占 93% 与 97%。合成形状上逐行 `dot_i8` 是 14–15 GMAC/s：每个点积只有两条四路累加链，每次加法等上一次；每读一个 int8 都单独扩成 f32。`docs/measurements.md` 里「约 12.5 GMAC/s，接近单核峰值，只能少算」的结论把单个点积的延迟上限当成了核的吞吐上限。

另一半是重复计算。池里候选大量共享开头（握紧…、我今天…），`SentenceModel::score` 逐候选从上文起算：52 条一共 2094 个前向位置，按 token 前缀去重只有 1134 个（54%）。`Reranker` 的按键路径已经按位置续算，但每个候选单独调用一次，每次只新增 1 到 3 行，线性层永远是一行一行地做。

## Decision

三处改动，全部保持分数逐位不变，不改公开接口，不加依赖，不用 unsafe，Rust 1.75 可编译。

1. **线性层按行分块。** `linear_into` 把输入行按 8 行（剩 4 到 7 行时再加一个 4 行块）转成按输入维存放 `[input][row]`，每个权重行只扩成 f32 一次，然后用 `dot_block` 同时乘 8 行：向量的那一维是行，权重按元素广播，16 条独立累加链。每行每个 lane 仍按 `l, l+8, l+16, …` 的顺序累加，lane 先后求和，尾部逐个加，乘 scale、加 bias 的顺序不变，所以每个元素和 `dot_row` 逐位相同。剩下不足 4 行的仍走原来的逐行点积。
2. **`SentenceModel::score` 一次决策只跑一批。** 候选按 token 前缀建成树，每个不同的前缀位置只算一次；所有位置在 `run_batch` 里一层一层一起过线性层，注意力按每行自己的祖先链去取 KV。词表归一化 `log_normalizers_into` 也按同样的块成批算，归一化常数的最大值与指数求和顺序与 `project` 相同。累计分按原来 `run_tail` 的加法顺序重算。
3. **`Reranker` 先规划再成批。** 只看 token：每个候选完全命中哪条、或从哪条旧轮/本轮的运行续算多少个字，规则和并列取舍与逐候选循环完全相同（完全命中先旧轮后本轮；最长共享前缀取最后一个同长项）。然后本次决策的全部新位置——包括要补算的末位置——在一批里算完，再按原来 `TailRun::joined` 的分组（`carried + rest`）拼回累计分、KV 和隐藏状态。需要归一化的状态一起投影，再写进各自的 `OnceLock`。前向位置数与投影次数和逐候选循环相同，测试直接比较这两个计数。

原来逐候选的 `run_tail`、`run_tail_states`、`TailRun::resume`、`TailRun::joined`、`score_against` 留作 `#[cfg(test)]` 的对照实现，测试用它们逐位核对。

## Existing decisions

- [按输出行分组](../../rejected/bug-fix/2026-10-15-matrix-row-batching.md)：同一输入对四个输出行，编译器跨输出行打包、出现大量 `tbl` 重排，回退 61–74%。本篇不交错输出行。
- [成对输入](../../rejected/testing/2026-10-17-linear-paired-inputs.md)与[临时展开行](../../rejected/testing/2026-10-17-linear-temporary-row-dequant.md)：都让多行共享一次权重转换，但输入仍按行存放，前者被编译器打成跨行两 lane 运算并逐元素标量转换，后者 4 行和 12 行只快 9–13%，没有过门槛。本篇的差别是把输入块转置成按输入维存放，向量化的维度变成「行」，权重按元素广播（`fmul.4s v, v, w[k]`），同时让一次调用的行数从 1–6 变成整次决策的几十行；同一台机器上 8 行块 24–27 GMAC/s，4 行块 24 GMAC/s，逐行 14–15。这几个数是写原型时在合成形状上量的，逐形状的表没有保存下来，之后也没有重测。
- [安全向量类型](../../rejected/testing/2026-10-23-safe-vector-dot.md)：不引入 `wide`，本篇仍只靠自动向量化。
- [同批候选缓存](../../implemented/bug-fix/2026-10-15-same-batch-cache.md)、[完全命中复用](../../implemented/bug-fix/2026-10-15-identical-rerank-cache.md)、[末位置按需计算](../../implemented/bug-fix/2026-10-15-defer-terminal-forward.md)、[共享状态归一化](../../implemented/bug-fix/2026-10-15-shared-state-normalization.md)：复用规则、优先级、末位置只在续算经过时才算、每个状态只投影一次，全部保持；本篇只改变这些计算在什么时候、和谁一起做。
- [前馈缓冲](2026-10-16-feed-forward-scratch.md)：`FeedForwardScratch` 多带一个 `LinearScratch`（转置块与一行权重），随前馈缓冲复用。

## Alternatives considered

- **FMA 或把输入也量化成 int8 用 `sdot`**：快得多，但改变舍入，分数不再逐位相同，不采用。
- **`std::arch` 手写 NEON / AVX2**：本 crate `unsafe_code = "forbid"`，Rust 1.75 上内建函数还要 `unsafe` 调用；自动向量化的转置布局已到 24–27 GMAC/s。
- **多线程**：用 `std::thread::scope` 在每次矩阵乘里按输出列切分做过原型（未提交）。24.9M 从 22.9 ms 降到 4 线程 13.0 ms；4.25M 在 2 到 4 线程时反而更慢，每次决策要起 33 次线程组，起线程的开销比 4.25M 一次矩阵乘还大。要拿到收益需要每次决策常驻的线程组和一个公开的线程数开关，移动端还要考虑功耗，留给维护者决定，不在本篇。
- **新依赖（rayon、Metal、ONNX Runtime）**：不加，见 PR 说明里的建议。

## Verification

2026-10-30 在 Apple M4 Pro 上复核，`origin/main` 为 `154eb5c`。没有重新计时，下面全是对与错的检查。

- `reference/`：`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`（debug，与 CI 相同）和 `cargo test --release` 都通过：50 项单元测试、15 项模型文件测试，13 项手动测试平时 ignored。Rust 1.75.0 的 `cargo check --all-targets` 通过，`reference/ffi` 同样通过。`ffi` 的 fmt、clippy、测试和 `tests/smoke.sh` 通过；本机没有 `cbindgen`，头文件一致性留给 CI，`ffi/src` 本身没有改动。
- 手动真实模型测试：`MSIME_NEURAL_MODEL_DIR` 指向两份发布权重（SHA-256 `86ac5295…` 与 `0a6ecba6…`），release 下 `real_models_batched_decisions_match_one_candidate_at_a_time`、`real_model_forward_matches_legacy_bits`、`real_embedding_matches_frozen_bits` 通过。第一项把池里 52 条逐字打一遍（每三条一条无前文，其余带「今天下午」），每次决策比较分数、保留下来的每条运行（累计分、各层 KV 及其容量、隐藏状态与归一化常数、末位置）、前向位置数与投影次数，另外比较 `score` 与逐候选的 `score_against`。带计时预算的手动测试没有跑。
- wasm32-wasip1（Rust 1.97.1）：不加与加 `-C target-feature=+simd128` 各编一份测试，在 Node 26 的 WASI 下单线程跑，50 项单元测试和上面第一项真实模型测试都通过。`wasm32-unknown-unknown` 的 release 编译通过。wasm 上比的是成批与逐候选两条路径，不是 wasm 与本机。
- 跨构建对照：`origin/main` 与本分支各编一份 `pool` 示例，两份权重各跑 `--passes 1`，去掉 `ms` 字段后输出逐字节相同（52 行）。另写一个不提交的临时示例，在两个构建上把池里每条用例逐字打一遍，无前文、带前文各一遍，每份权重 774 次 `Reranker` 决策和 104 次 `score`，每个分数按 f32 的位输出，两边逐字节相同。这一项不依赖测试里那份逐候选实现抄得对不对。
- 用 cargo 的共享 `build.build-dir` 时，两个检出编同名同版本的 crate 可能直接用上对方的产物：复核时第一次得到的两份 `pool` 哈希相同，跑出来也一样快。对照的两个构建要各用独立的 build-dir 和 target-dir，上面的对照都是这样编的。
- 52 条候选一共 2094 个前向位置、按前缀去重 1134 个，用脚本重数过。
- MSIME 没有重跑。计时那次在 MSIME `e6b494be61` 上把 `chinese-ime-lm` 分别换成改动前后的源码编出两份评测程序（哈希不同），六个评测集、`--keyboard-neural` 下五个整句集、挂 24.9M 做停顿重排的五个整句集各跑一遍；复核时把留下的 32 个输出文件（候选 jsonl 与报告）逐个 `cmp`，前后全部相同。那次三个 typing 集两边都因参数解析报错，没有可比的输出。

## Consequences

- 收益：一次冷决策在 52 条的池上约快 3 倍，按键路径 p95 快 21% 到 37%（`--typed` 与 MSIME 按轮配对相比，表在 `docs/measurements.md`）；分数逐位不变，所以评测结果、宿主里依赖分数的阈值都不用重定。
- 代价：`lib.rs` 多了一套成批的规划与拼装（`run_batch`、`Batch::anchor`、`Batch::state`），比逐候选循环难读；原来的逐候选实现只在测试里存在，以后改复用规则要两边一起改，测试才有意义。
- 一次决策的中间缓冲按批申请，峰值内存随这次决策的新位置数增长；52 条的冷决策是一千多行乘各层宽度，没有量过常驻内存的变化。
- 逐位不变是硬约束：以后要用 FMA、`sdot` 或多线程按列切分，都得先决定是否放弃这条，不能顺手做。
