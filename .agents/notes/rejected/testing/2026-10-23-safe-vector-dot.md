# Agent Note: 用安全向量类型保持量化点积的八路累加

Status: rejected — 兼容版本的原型未减少目标转换指令，没有取得接入依据

## Problem

主项目九键仍未达到 16 ms，实际采样的模型热点仍包括 `dot_i8` 与 `linear_into`。当前 ARM64 已自动向量化和外提精度分派，重复尝试旧循环组织没有依据。原 int8 到 f32 转换由编译器从标量 lane 表达生成，旧指令中有 `tbl` 重排；需要确认显式向量类型能否减少实际转换与打包成本。

## Proposal

先以 `wide` 0.7.33 的安全 API 做局部原型：每八个 int8 转成 `i32x8` 再 `round_float`，与 `f32x8` 输入逐 lane 相乘并累加；仍维持八个部分和、原顺序的标量归约和不足八个的原尾部。保持 int8 常驻表示，不使用 FMA、不增加输入或输出行交错、不改变 scale/bias，不编写 unsafe 或架构分支。先核对库源码和实际机器码；不能减少目标成本就撤回。原型依赖先只用于试验，只有完整收益证据才接入生产依赖。

## Existing decisions

[行交错](../../rejected/bug-fix/2026-10-15-matrix-row-batching.md)、[成对输入](../../rejected/testing/2026-10-17-linear-paired-inputs.md)与[临时展开行](../../rejected/testing/2026-10-17-linear-temporary-row-dequant.md)均保留否决；它们改变跨行调度，本篇改变单行内运算表达。[直接行分派](../../rejected/testing/2026-10-16-linear-direct-rows.md)已证明分派外提，不重做。[词表行遍历](../../implemented/testing/2026-10-16-project-row-stream.md)继续持有完整投影顺序。检索全部活跃笔记，没有显式安全向量库的相同实现、完全吸收或过时提案。

`wide` 的[固定版本文档](https://docs.rs/wide/0.7.33/wide/struct.i32x8.html)提供 `From<&[i8]>` 和 `round_float`；新版本的 MSRV 已提高，不能不固定兼容系列。实际支持 Rust 1.75 必须通过构建核对，不能用当前编译器代替。

## Alternatives considered

- **沿用自动向量化**：无依赖与适配成本，已有有效向量指令；如果显式表达没有足够收益，保留它。
- **手写 NEON 或 AVX 内核**：可直接控制符号扩展，但引入自身 unsafe 与平台分支，不采用。
- **更多部分和或 FMA**：可能提高吞吐，但改变舍入和原位模式，不采用。

## Acceptance criteria

先冻结当前完整 `dot_i8`、linear 与 project，生产入口对照需先通过逐位检查，未改实现的同预算必须失败。原型先比较机器码与局部配对；完整 linear 的基宽 192/768、qkv/proj/fc/out、1/4/12 输入位置、float/int8 共 48 形状，加完整 project 的宽 192/768、float/int8 共四形状。每形状至少 21 对，交替先后，每臂校准至少 5 ms；量化 192 基宽目标几何均值 <0.90，任一控制不得 >=1.05。保留全部样本，不挑失败形状或降低阈值。

宽 0/1/7/8/9/15/16/17/192/768、不等长切片既有行为、非整数尾数、宽指数、相消、非有限值及负零对照。实际模型评分/分布逐位不变；若局部门槛通过，再跑完整 bench 表、Rust 1.75、全量测试、Clippy、fmt、笔记及主项目锁定资源质量和无干扰九键 ABBA/quick。上游单独 PR 合并，再固定提交接入；失败则恢复生产并只交付可复现的有效负结果。

## Risks

安全库内部有架构实现，新增依赖、代码体积和许可证记录是成本；必须核对三类宿主目标与 WASM 的编译，不能把本机 ARM64 结果泛化。显式 SIMD 可能仅改变寄存器布局而没有收益，短尾也可能变慢。这里只提出调查，未声称存在缺少向量化的产品缺陷或九键达标。

## Investigation and decision

固定本库远端默认分支 `main` 的 `4e745be72f1c49e9c7b5dadea819fbb1fcda0e13`；相对主项目固定 pin `15caab4` 只有依赖和 workflow 更新，`reference/src/lib.rs` 没有差异。独立检出未取相邻仓库的未提交内容，也没有改 Cargo 的上游缓存。

`wide` 0.7.33 是版本元数据中最后一个未撤销且声明兼容本库 MSRV 的版本（声明 1.61）；0.7.34 已撤销并要求 1.89，0.8 系列也要求 1.89。只把 0.7.33 加为临时 dev-dependency，未接入生产依赖。该版本 `i32x8::from(&[i8])` 通过普通数组转换；`from_u8x16_low` 与 `from_i16x8` 在 ARM64 上也没有专用扩展实现。本轮只实施一种表达，没有继续盲调更多循环。

冻结旧点积的聚合逐位对照先通过；原型同一检查也通过，覆盖十种基础长度、每侧四种附加长度，以及普通宽指数/非整数尾数和负零、正负无穷、NaN。这个检查不等于完整模型质量或所有 NaN 载荷的等价证明。临时测试有 unused import 编译警告，没有把它冒充 Clippy 通过。

旧入口的局部配对预算等待连续 30 秒无编译且一分钟 load<=10，180 秒未满足，未开始任何计时。全部等待点保留。没有红测性能失败，也没有候选性能结果；等待超时不能写成性能预算失败。

固定本机 ARM64、Rust 1.97.1 / LLVM 22.1.6 的 release 测试程序中，原生产点积循环为 12 条指令，候选为 14 条。两者均含两次 `tbl.16b`、两次 `scvtf.4s`、两次 `fmul.4s` 和两次 `fadd.4s`；候选使用两次额外的指针 `add`，旧版通过加载后自增更新指针。完整反汇编与可机械重算的循环统计保留。测试包装器的机器码不能代替主项目发布构建；指令数也不能直接换算时间比值，但它没有支持消除转换/打包成本的主要假设。

本轮不采用显式向量库，不为缺乏接入依据的原型继续等待、运行完整 48+4 形状、模型 bench 整表、Rust 1.75、跨平台编译、质量、九键 ABBA 或主项目 quick。生产源码、清单和锁文件通过 `finally` 逐字恢复基线；主项目 pin 不变。全部合成探针、接线 patch、构建记录、二进制哈希、等待与恢复证据见[调查目录](../../../../docs/measurements/2026-10-23-safe-vector-dot/README.md)。

## Consequences

保留自动向量化和原依赖边界，避免没有收益证明的新依赖；代价是 int8 点积热点和九键 16 ms 超预算继续存在。此结论只针对固定兼容版本和本机原型，不否定所有安全 SIMD 库或未来工具链；若重访应先给出实际减少目标成本的编译结果，再进入完整性能和质量验证。
