# 训练管线

模型的用途、不适用的场景以及语料许可，见仓库根目录的 README。

| 文件 | 作用 |
|---|---|
| `corpus.py` | 构建规范化语料，每行一句中文 |
| `model.py` | 字级 Transformer，两档尺寸预设 |
| `train.py` | 建词表、打包 token 到内存映射数组、训练 |
| `export.py` | 写出 safetensors，并打印安装器需要的资源锁条目 |
| `rerank_eval.py` | 对录制下来的候选列表打分，分桶报告结果 |

## 语料源

| 源 | 许可 | 产出 | 说明 |
|---|---|---|---|
| `c4` | ODC-BY | 按需，流式 | 网页文本，唯一能达到语言模型所需规模的来源 |
| `lccc` | MIT | 3.18 亿字 | 开放域对话，补口语语域 |
| `wiki` | CC BY-**SA** 4.0 | 2.01 亿字（整个转储的上限） | 百科体散文 |
| `docs` | CC BY 4.0 / CC BY-SA 2.5 / Apache-2.0 | 520 万字 | 中文技术文档 |

`wiki` 和 `docs` 带有传染性许可的成分，发布权重时不使用。

## 规范化

只保留汉字（CJK 基本区和扩展 A）。拉丁字母、数字、标点一律作为**切分边界**而非替换——推理时交给模型的候选来自拼音解码器，除汉字外不含别的东西，训练数据的形状必须与之一致。

简繁做两级判别：文档级按**比例**判定（引用一两个繁体字的简体文章不算繁体），保留下来的文档内部，片段级"出现即丢"。只按"出现即丢"判文档会丢掉八成维基——简体条目大量引用繁体书名人名。

## 指定尺寸

`--preset keyboard` / `--preset desktop` 是两组测过的形状（见 `docs/measurements.md` 的表）。扫描要的是两档之间的形状，所以 `--vocab` / `--n-layer` / `--n-head` / `--n-embd` / `--context` 可以逐项覆盖预设，没给的项仍由预设决定：

```sh
python neural/train.py --corpus data/c4.txt data/lccc.txt --out runs/l6-e192 --n-layer 6 --n-embd 192 --n-head 4
```

`n_embd` 必须能被 `n_head` 整除——注意力头平分宽度。除不尽会在解析命令行时就报错退出，而不是等到第一次前向；否则报错发生在建词表和打包语料之后，那在真实语料上是将近一小时。

每个 run 的输出目录里写一份 `config.json`：模型形状（词表大小取建表后的实际值）、基于哪个预设，以及语料、步数、批大小、学习率、warmup 和随机种子。它在第一步之前就写，因为 `checkpoint.pt` 只在验证损失改善时才写——扫描里被提前掐掉的那些 run，否则事后没有任何东西说得清它是什么配置。

## 已知的坑

- 维基转储会被中途截断，而 urllib 把截断的响应报成正常的流结束。下载会比对 content-length、断点续传、失败到第五次才报错。
- `pages-articles` 里除条目外还有模板和元页面，只取命名空间 0。
- C4 分片 0 的首条文档在源文件里就是乱码（`�` 已经烘进文件），所以单个分片失败要跳过而不是当作语料结束。

## 查看训练进度

训练动辄几小时，通常是脱离终端启动、输出重定向到别处的。那样 stdout 会被管道缓冲，进度只存在于一个没人读得到的缓冲区里，直到进程结束——而那正是它不再有用的时刻。

所以进度同时写进输出目录，每次评估都刷盘：

| 文件 | 内容 |
|---|---|
| `progress.log` | 每次评估一行，带时间戳，追加写 |
| `progress.json` | 当前步数、损失、困惑度、已用时间、**每千步秒数** |

```sh
cat runs/desktop/progress.json
```

**不要拿 `checkpoint.pt` 判断进度。** 它只在验证损失改善时才写，所以它的 `step` 是下界，时间戳会在任何没有改善的阶段停住不动——看起来像训练卡死了，而其实一切正常。`progress.json` 每次评估都写，无论损失是否改善。
